## What it does

- **Who sees the gate.** First visit to LO Workspace (internal app only, never the Partner Workspace portal), when all of these are true:
  - the user holds custom permission `External_LO`;
  - `External_LO_Onboarding_Complete__c` is false;
  - `LoWs_Gate_Passed_At__c` is blank.
  So existing users who finished setup (the pilot, Brandon, Chris) never see it (Q17).
- **Order (Q4).** Get connected → existing setup Q&A (Perfect Week wizard) → tour (O4). Both connections and setup are required (Q5).
- **Gate rows:**
  - **Zoom** (required). A live `GET callout:Zoom_User_OAuth/v2/users/me`; a 200 stamps `LoWs_Zoom_Verified_At__c`. It runs on every load and on "Check again" until it is green.
  - **Outlook** (required). "I've connected" stamps `LoWs_Outlook_Attested_At__c`. EAC status cannot be queried.
  - **RingCentral** (required only when `LoWs_RingCentral_Required__c`). It is green when all three hold: `Rc_Extension_Id__c` is set, `RingCentral_Refresh_Token_DateTime__c` is set, and `RingCentral_Refresh_Token_Expired__c` is false. "Connect RingCentral" opens the existing authorize URL (same URL as `RingCentralUserAuthController`, `state=<userId>`). The callback page `RingCentralAuthPage` (the External LO profile already has access) stores the tokens and fills in the extension id.
  - **Salesforce mobile app** (recommended, never blocks). Green when LoginHistory shows `Salesforce for iOS` or `Salesforce for Android` in the last 30 days. `Application` cannot be filtered in SOQL, so the code filters on `LoginType='Remote Access 2.0'` and groups by Application.
- **Waived rows** count as ready. When every required row is green or waived, `LoWs_Gate_Passed_At__c` is stamped, a success card appears ("Let's go"), and the shell continues to the existing setup flow.
- **Pass alert (Q38).** A bell (`LO_Workspace_Lead` type) plus an email reading "<Name> is live in LO Workspace". It goes to every active holder of `LO_Workspace_Oversight` (Chris, Brandon, Adam) or `LO_Workspace_Onboarding_Admin`. The bell targets the LO's User record.
- **After the gate (Q14).** The gate is never shown again. On Perfect Day, a dismissible red banner (once per browser session) lists required connections that are broken now:
  - Zoom is re-checked live on each workspace load;
  - RingCentral is checked from the token fields;
  - Outlook cannot be checked.
  It only appears for users who passed the gate.
- **Oversight tab (Q34/Q36).** A new "Onboarding" table with one row per active LO in the `External_Loan_Officer` role. Columns: setup, Zoom, Outlook, RingCentral (n/a when not required), mobile app, tour. **Admin only** (custom permission `LO_Workspace_Onboarding_Admin`):
  - **Waive** on a red Zoom / Outlook / RingCentral cell. A reason is required, and it is logged to `Custom_Log__c` with Source `LO Workspace Onboarding Waiver`.
  - **Reset onboarding** (with a confirm step). It clears setup-complete, attestations, verifications, gate-passed, waivers and both tour fields, and keeps goals, plan and data. Logged with Source `LO Workspace Onboarding Reset`, including the previous values.
  Brandon and Adam are System Administrators, so the profile could not be the gate. A custom permission held only by Chris is.
- **New-LO alert (Q30).** `UserTriggerHandler.afterInsertOrUpdate` calls `LoWsOnboardingGateService.alertNewLos`. When a user becomes active in the `External_Loan_Officer` role (on insert, activation, or role change), holders of `LO_Workspace_Onboarding_Admin` get an email and a bell: "Set up <Name>'s landing page". The message includes the endpoint, where to find the secret, and the username. It does no DML, so it is mixed-DML safe.
- **No-"External" wording (coordinator request).**
  - The shell user-role line shows "Loan Officer" in LO Workspace. The portal keeps label `ExtLO_Shell_User_Role`; the label value is unchanged.
  - The Oversight empty state now reads "No active LO Workspace loan officers yet."

## Open questions

- **Zoom callout per load.** After the gate, each LO Workspace load makes one Zoom callout for the banner. Acceptable at this size; switch to a daily cache if it ever gets slow.
- **Mobile window.** The mobile row only sees the last 30 days of LoginHistory, because EAC floods LoginType "Remote Access 2.0" and Application cannot be filtered. An LO who has not opened the app for 30 days shows red on the roster (recommended only, never blocking).
- **Q38 recipients.** "The LO's manager" is approximated as all Oversight holders (Chris, Brandon, Adam). There is no per-LO manager field.
- **Banner and the checklist row.** The banner covers both: there is no persistent checklist after the gate. A "Get connected" checklist page in LO Workspace could be added in O4 if wanted.
- **RingCentral auth flaw (pre-existing, not changed).** The RingCentral callback binds tokens to whatever user Id is passed in `state`.
